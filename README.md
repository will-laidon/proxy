## 2. Project Overview

### The Problem

SimpleMDG products use **two separate authentication systems**:

1. **SimpleMDG internal app** — authenticated via SAP (XSUAA/OAuth)
2. **Client's backend system** — authenticated via a separate browser login with its own session cookie

When a developer works on a SimpleMDG UI5 app that must call APIs from the client's backend, the UI5 app runs under SimpleMDG's SAP authentication but the client's backend requires the separate client session cookie. The two auth systems are independent.

### The Solution

ProxyHub sits between the UI5 frontend and the client's backend, forwarding every request with the stored client session cookie embedded — so the developer does not need to manually re-authenticate on every API call.

```
┌─────────────────────────────────────┐    ┌─────────────────┐    ┌──────────────────────────┐
│  SimpleMDG UI5 App (SAP auth)       │    │  ProxyHub        │    │  Client Backend System   │
│                                      │    │  (localhost:3000) │    │  (real client system)     │
│  ui5-middleware-simpleproxy          │───▶│                   │───▶│                          │
│  mounts /srv-approver → localhost:3000   │  Adds stored       │    │  Validates cookie +      │
│                                      │    │  client cookie    │    │  returns data            │
└─────────────────────────────────────┘    └─────────────────┘    └──────────────────────────┘
```

### How It Works

1. The developer logs into the client system via Edge browser and copies the authenticated `fetch` request from the Network tab.
2. The request snippet — including `cookie`, `x-csrf-token`, `x-correlation-id`, and other headers — is pasted into `src/app.ts`.
3. The `extractHeadersFromAxiosCode` utility parses the snippet and extracts the headers.
4. `SV_URL` is derived from the `Referer` header in the snippet (this is the client's backend origin).
5. When the UI5 app makes a request through `ui5-middleware-simpleproxy` to `http://localhost:<PORT>/...`, ProxyHub forwards it to `SV_URL + path` with the stored headers appended.

> **Note:** The cookie expires after a set period and must be refreshed manually (we will automate this in a future update). To refresh, simply copy a new fetch snippet with valid headers and update `src/app.ts`.

2. Scroll to the **Context** section in the issue description

## 5. Browser Profile Setup

Use a **separate Microsoft Edge browser profile for each client environment**. This isolates cookies so you can be logged into multiple client systems simultaneously without session conflicts.

### Why Separate Profiles?

When you log into Client A's system, Edge stores the session cookie for that domain. If you then log into Client B's system in the same profile, the cookie for Client A may be overwritten or conflicted. Using dedicated profiles ensures each client's authentication is isolated.

### Steps to Create an Edge Profile

1. Open Microsoft Edge
2. Click the profile icon in the top-right corner
3. Click **Add profile**
4. Give the profile a descriptive name matching the client (e.g., `Landis Gyr Dev`)
5. Click **Continue**
6. Optionally sign in with a Microsoft account (not required for development)
7. The new profile opens in a separate window

<!-- Screenshot: [Edge Profiles] Edge browser settings showing multiple profiles -->
<!-- Caption: Create a separate Edge profile for each client environment. This keeps session cookies isolated between clients. -->

### Logging into the Client System

1. Open the profile dedicated to the target client
2. Navigate to the client system URL (from the Jira ticket's CR link)
3. Log in using the credentials from the **User ID** field in the Jira ticket
4. Verify the login was successful by navigating to **Main → My Request**

<!-- Screenshot: [Edge Profile] Client system logged in under a dedicated Edge profile -->
<!-- Caption: Logged into the Landis Gyr Dev client system using its dedicated Edge profile. Verify access by navigating to Main → My Request. -->

## 8. How to Obtain and Update the Authentication Headers

The proxy forwards requests with a hardcoded authentication cookie. To update the cookie when it expires (or when switching to a new client):

### Step 1 — Log in to the Client System

Using the appropriate **Edge browser profile** (Step 5), log in to the target client system and navigate to **Main → My Request**.

### Step 2 — Open DevTools Network Tab

1. Open Microsoft Edge DevTools (`F12` or `Ctrl + Shift + I`)
2. Go to the **Network** tab
4. Refresh the page or trigger a data fetch (e.g., scroll the request list)

<!-- Screenshot: [DevTools Network] Network tab showing getBusinessRequest request -->
<!-- Caption: In Edge DevTools Network tab, find the getBusinessRequest POST request. -->

### Step 3 — Copy the Request as Node.js Fetch

1. Find the `getBusinessRequest` POST request (or any authenticated POST request to the client backend)
2. Right-click the request row
3. Select **Copy** → **Copy as Node.js fetch**

<!-- Screenshot: [DevTools Network] Right-click menu showing Copy as Node.js fetch option -->
<!-- Caption: Right-click the request and select Copy → Copy as Node.js fetch. This copies the full request including headers and body. -->

### Step 4 — Update `src/app.ts`

1. Open `src/app.ts` in your editor
2. Locate the `raw` constant at **line 27**
3. Replace the entire existing content of `raw` with the copied fetch snippet

```typescript
// src/app.ts — line 27
let raw = String.raw`fetch("https://<client-system-url>/srv-process/CommonProcessService/getBusinessRequest", {
  "headers": {
    "cookie": "__VCAP_ID__=...; JSESSIONID=...",
    "x-csrf-token": "...",
    "x-correlation-id": "...",
    // ... other headers
  },
  "body": "{\"businessRequest\":{...}}",
  "method": "POST"
});`
```

The `extractHeadersFromAxiosCode` utility in `src/utils.ts` parses this string at startup and extracts the headers object. The `SV_URL` is derived from the `Referer` header inside the snippet.

### Step 5 — Restart the Proxy

After updating `src/app.ts`, restart the proxy server:

```bash
npm run main   # or npm run admin
```

The new cookie and `SV_URL` will be loaded on startup.

<!-- Caption: Paste the copied fetch snippet into the raw constant in src/app.ts (line 27), then restart the proxy to pick up the new authentication headers. -->

## 9. Configuring the UI5 App to Use the Proxy

In the `ui5.yaml` of your target folder (`main` or `admin`), add or confirm the `ui5-middleware-simpleproxy` middleware configuration:

```yaml
server:
  customMiddleware:
    - name: ui5-middleware-simpleproxy
      mountPath: /srv-approver
      afterMiddleware: compression
      configuration:
        baseUri: http://localhost:3000/srv-approver/
        limit: 10mb
```

| Property | Value | Description |
|----------|-------|-------------|
| `mountPath` | `/srv-approver` | URL prefix that gets routed through the proxy |
| `afterMiddleware` | `compression` | Run after the compression middleware |
| `baseUri` | `http://localhost:3000/srv-approver/` | Proxy address + mount path (port must match the running npm script) |
| `limit` | `10mb` | Maximum request/response body size |

### Request Flow with the Middleware Configured

1. UI5 app makes a request to `/srv-approver/srv-process/CommonProcessService/getBusinessRequest`
2. `ui5-middleware-simpleproxy` intercepts the request and forwards it to `http://localhost:3000/srv-approver/...`
3. ProxyHub receives the request and forwards it to `SV_URL + /srv-process/CommonProcessService/getBusinessRequest` with the stored auth headers
4. Client backend validates the cookie and returns the response
5. ProxyHub returns the response to the UI5 app

## 10. Cookie Expiry and Re-authentication

The session cookie stored in `src/app.ts` expires after a set period (determined by the client system). When the cookie expires, API calls will start returning **401 Unauthorized** or authentication errors.

### Signs the Cookie Has Expired

- Browser DevTools shows `401` responses from the client backend
- UI5 app shows data loading errors or blank data panels
- Proxy server logs show `401` error responses

### How to Refresh

1. Open the appropriate **Edge browser profile** for the target client
2. Navigate to the client system (you may need to re-log in)
3. Follow **Step 8** to copy a fresh `fetch` request
4. Update the `raw` constant in `src/app.ts` (line 27)
5. Restart the proxy server

> **Automation:** Manual cookie refresh is a known inconvenience. Automated cookie refresh is planned for a future update.

## 11. Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `SERVER IS UP ON PORT: 3000` does not appear | Port already in use | Kill the existing process using the port, or set a different `PORT` env variable |
| `401 Unauthorized` on API calls | Cookie expired | Follow Step 8 to obtain fresh headers |
| `500 Internal Server Error` from proxy | `SV_URL` in `src/app.ts` does not match the current client backend URL | Check the `Referer` header in the copied fetch snippet — the origin must match the active client system |
| CORS errors in the UI5 app | `baseUri` in `ui5.yaml` points to the wrong proxy port | Verify the port in `baseUri` matches the running npm script (`3000` = `main`, `3001` = `admin`) |
| Image/file upload fails | Browser policy for file uploads | Use **Microsoft Edge** for development — the company's file upload policy is aligned with Edge |
| `extractHeadersFromAxiosCode` returns `null` | Fetch snippet not in valid format | Ensure the copied snippet is a complete `fetch(...)` call from Edge DevTools Network tab |
| Proxy starts but no requests are forwarded | `ui5-middleware-simpleproxy` not configured in `ui5.yaml` | Add the middleware configuration to `ui5.yaml` (Step 9) |

### Common Port Conflicts

```bash
# Windows: find and kill process on port 3000
netstat -ano | findstr :3000
taskkill /PID <PID> /F

# Then restart the proxy
npm run main
```

## Key Source Files

### `src/app.ts`

```typescript
// Line 27 — paste the copied fetch snippet here
let raw = String.raw`...`

// Line 49 — headers are parsed from the raw snippet
const headers = extractHeadersFromAxiosCode(raw)

// Line 50 — SV_URL is derived from the Referer header
const SV_URL = new URL(headers.Referer).origin

// Line 24 — default port
const PORT = Number(process.env.PORT) || Ports.A  // Ports.A = 3001

// Line 116 — server startup
app.listen(PORT, ...)

// Line 87 — all requests (except images) are forwarded here
app.use('/*', async (req, res) => {
  await axios.request({
    method: req.method,
    url: `${SV_URL}${req.originalUrl}`,
    data: req.body,
    headers,  // hardcoded auth headers from raw snippet
  })
})
```
